## 1. 概要

「分散創造」は、CLIP STUDIO PAINT やメディバンペイントのようなイラスト・漫画制作ツールに、Git のような**分散バージョン管理**と、Winny や暗号資産のような**中央管理者を持たない、素材・拡張機能の P2P 配布基盤**を組み合わせたソフトウェアである。

作品の制作履歴・分岐・共同制作を分散して扱えること、そしてブラシ・トーンなどの素材や拡張機能を、特定の企業やサーバーに依存せずに配布・入手できることを目指す。

## 2. 背景と目的

### 2.1 背景

- 既存のイラストツールでは、ブラシ・トーン・テンプレートなどの素材や拡張機能（プラグイン）の配布が、ツール提供企業などが運営する配布サービスに依存している。そのため、運営者の規約変更・決済代行業者や広告主の意向・サービス終了によって、素材や拡張機能が公開停止・削除されたり、入手できなくなったりするリスクがある。
- イラストや漫画は試行錯誤の多い制作物だが、「別案を試す」「以前の状態に戻す」「複数人で並行作業する」ための仕組みが、ファイルのコピーや手作業に頼っている。
- 漫画制作では、ネーム段階でのコマ割り変更と、各コマの作画作業が互いに干渉しやすい。

### 2.2 目的

1. プロ水準のイラスト・漫画制作機能を提供する。
2. 制作データを Git 同様にコミット・ブランチ・マージ・クローンできるようにする。
3. 中央サーバーを持たない設計により、第三者が素材・拡張機能を一方的に削除・改変・公開停止できない構造を技術的に実現する。
4. 漫画制作において、コマ割り（ページ構成）とコマ内の作画を独立して管理できるようにする。

## 3. 用語定義

| 用語 | 定義 |
| --- | --- |
| 作品リポジトリ | 1 つの作品（イラスト 1 枚、漫画 1 冊など）の全データと全履歴をまとめた単位。Git のリポジトリに相当する。 |
| コミット | ある時点の作品状態のスナップショット。作者の署名つきで記録される。 |
| ブランチ | 作品の分岐した系統。別案・差分・共同作業者ごとの作業線などに使う。 |
| オブジェクト | レイヤー、ストローク、画像タイル、コマ定義など、ハッシュ値で識別されるデータ片。 |
| ピア | 本ツールを実行し、ネットワーク上で他の端末とデータをやりとりする各端末。 |
| 素材 | ブラシ・トーン・パターン・画像素材・カラーパレット・コマ割りテンプレートなど、作品制作に使う部品。 |
| 拡張機能 | 本ツールに機能（ツール・フィルター・書き出し形式・UI パネルなど）を追加するプログラム。 |
| パッケージ | P2P で配布する単位。1 つ以上の素材または 1 つの拡張機能と、作者・利用条件などの情報をまとめたもの。 |
| コマ割りレイヤー | 漫画モードで、ページ上のコマの形状・配置・読み順などを定義するデータ。 |
| コマ内容 | 漫画モードで、各コマの中に描かれる絵・セリフ・効果などのデータ。 |

### 4.3 素材・拡張機能の P2P 配布・検閲耐性機能

素材・拡張機能のパッケージの公開・入手を、特定の管理者に依存せずに行うための機能群。
作品そのものは P2P 配布の対象としない（7 章参照）。

| ID | 要件 | 優先度 |
| --- | --- | --- |
| F-P2P-01 | 中央サーバーなしで、ピア同士が直接パッケージを交換できること | 必須 |
| F-P2P-02 | ピアの発見に分散ハッシュテーブル（DHT）など、単一障害点のない仕組みを使うこと | 必須 |
| F-P2P-03 | パッケージは内容のハッシュ値で参照され、1 つでもピアが保持していれば取得できること | 必須 |
| F-P2P-04 | 利用者の識別は公開鍵で行い、メールアドレス・電話番号・実名の登録を必須としないこと | 必須 |
| F-P2P-05 | 通信は暗号化すること | 必須 |
| F-P2P-06 | Tor・I2P などの匿名化ネットワーク経由の通信に対応すること | 推奨 |
| F-P2P-07 | パッケージを暗号化し、鍵を渡した相手だけが入手できる限定公開に対応すること | 必須 |
| F-P2P-08 | 開発者・配布元を含む第三者が、他人の端末にある作品・素材・拡張機能を遠隔で削除・改変・閲覧できる機能（キルスイッチ・バックドア）を持たないこと | 必須 |
| F-P2P-09 | 自動アップデートや外部通信で、利用者の意思に反してコンテンツ制限を後から追加できない設計とすること | 必須 |
| F-P2P-10 | 何を保持・中継するかは各利用者が自分で決められること（自分の端末に置くデータを選ぶ権利） | 必須 |
| F-P2P-11 | ソースコードをオープンソースとして公開し、誰でもフォーク・再配布できること | 必須 |
| F-P2P-12 | パッケージの発見のため、分散型のタグ・検索インデックスを持つこと | 推奨 |
| F-P2P-13 | パッケージに作者の電子署名を付け、作者本人が公開したものであることと、改ざんされていないことを検証できること | 必須 |

### 4.4 漫画モード

漫画モードでは、**コマ割り（ページ構成）**と**コマ内容（各コマの中身）**を別々のデータとして持ち、それぞれ独立してバージョン管理する。

#### 4.4.1 データ構造

```
作品（漫画）
├── ページ構成履歴           ← コマ割りの履歴
│   └── ページ n
│       ├── コマ枠（形状・位置・枠線・読み順）
│       └── コマ参照 → コマ ID
└── コマ内容履歴             ← コマ内の作画の履歴
    └── コマ ID
        ├── レイヤー群（下描き・ペン入れ・トーン・背景…）
        ├── セリフ・吹き出し
        └── 描き文字・効果
```

- コマ枠はコマ内容を **ID で参照する**だけで、画像データそのものは持たない。
- コマ内容は自分のキャンバス座標系を持ち、コマ枠の形状が変わっても内容側は変更されない（枠に対する位置・拡大率・切り抜きは参照側が持つ）。

#### 4.4.2 機能要件

| ID | 要件 | 優先度 |
| --- | --- | --- |
| F-MANGA-01 | ページサイズ・裁ち落とし・仕上がり線・基本枠を設定できること | 必須 |
| F-MANGA-02 | コマを分割・結合・変形・移動でき、斜めのコマや枠からはみ出す絵に対応すること | 必須 |
| F-MANGA-03 | コマ割りの変更を、コマ内容とは**別のコミット・別のブランチ**として記録できること | 必須 |
| F-MANGA-04 | コマ内容の変更を、コマごとに独立したコミット・ブランチとして記録できること | 必須 |
| F-MANGA-05 | コマ割りを変更しても、コマ内容の履歴が変化・破損しないこと | 必須 |
| F-MANGA-06 | コマ割りのブランチ（例：ネーム案 A / B）とコマ内容のブランチを自由に組み合わせてプレビューできること | 必須 |
| F-MANGA-07 | 1 つのコマ内容を別のコマ・別のページに付け替えられること | 必須 |
| F-MANGA-08 | コマ割り担当と作画担当が同時に作業しても、互いの変更が競合しないこと（別データのため） | 必須 |
| F-MANGA-09 | コマの読み順を設定し、読み順に沿ってコマを 1 枚ずつ表示するビューアを持つこと | 推奨 |
| F-MANGA-10 | 見開き表示・ページ一覧表示ができること | 必須 |
| F-MANGA-11 | コマ単位で作業担当者・進捗（ネーム／下描き／ペン入れ／仕上げ）を管理できること | 推奨 |
| F-MANGA-12 | 入稿用に、ページ単位で画像・PDF として書き出せること | 必須 |

#### 4.4.3 利用例

- ネームを直してコマの大きさを変えても、描き終わったコマの絵はそのまま残る。
- 「コマ割り案 A」と「コマ割り案 B」を、同じ作画データのまま並べて比べられる。
- アシスタントがコマ 3 の背景を描いている間に、作者が同じページのコマ割りを直せる。

### 4.5 素材・拡張機能

4.3 の P2P 配布で流通させる、素材と拡張機能そのものの要件。

#### 4.5.1 素材

| ID | 要件 | 優先度 |
| --- | --- | --- |
| F-ASSET-01 | ブラシ・トーン・パターン・画像素材・カラーパレット・コマ割りテンプレートを素材として作成・書き出し・読み込みできること | 必須 |
| F-ASSET-02 | パッケージに作者名・説明・利用条件（商用利用可否、改変可否など）を記述でき、入手前と使用時に表示すること | 必須 |
| F-ASSET-03 | 素材の版を管理し、更新版を入手した後も以前の版に戻せること | 必須 |

#### 4.5.2 拡張機能

拡張機能は審査を経ずに P2P で流通するため、悪意のあるプログラムから利用者を守る仕組みを必須とする。

| ID | 要件 | 優先度 |
| --- | --- | --- |
| F-EXT-01 | 拡張機能向けの公開 API（描画ツール、フィルター、書き出し形式、UI パネル）を提供すること | 必須 |
| F-EXT-02 | 拡張機能はサンドボックス内で実行し、ファイル・ネットワークなどへのアクセスは利用者が許可した権限に限ること | 必須 |
| F-EXT-03 | 導入時に、拡張機能が要求する権限を一覧表示し、利用者の同意を得ること | 必須 |
| F-EXT-04 | 拡張機能の更新は自動では適用せず、変更点と権限の変化を示して利用者が承認してから適用すること | 必須 |
| F-EXT-05 | 拡張機能を無効化・削除したときに、作品データが壊れないこと | 必須 |

## 6. 検閲耐性の設計方針と限界

### 6.1 方針

本ツールでいう「どんな表現規制も適用されない保証」は、**技術的な構造によって、第三者が素材・拡張機能を一方的に消したり隠したりできないこと**を意味する。具体的には次の方法で実現する。

- **単一の管理者を置かない**：中央サーバー・アカウント管理・審査機構を持たないため、運営者の判断や外部からの圧力による一括削除が構造的にできない。
- **内容アドレス方式**：パッケージはハッシュ値で参照されるため、どこか 1 か所を止めても、他のピアが保持していれば取得できる。
- **改ざん検出と署名**：パッケージが途中で書き換えられた場合は検出でき、作者の署名で本物であることを確かめられる。
- **オープンソース**：開発者が将来方針を変えても、誰でもフォークして元の方針で続けられる。
- **開発者自身も制限できない**：F-P2P-08・F-P2P-09 のとおり、開発者が後から制限を追加する手段を持たない。

### 6.2 限界（利用者に明示する事項）

- 本ツールが保証できるのは**技術的な構造**であり、**法律の適用を免除するものではない**。利用者は、自分のいる国や地域の法律に従う責任を負う。
- 公開したデータは他のピアに複製されるため、作者本人であっても**完全に取り消すことはできない**。公開前にこのことを利用者に明示する。
- 通信の暗号化や匿名化を行っても、利用者の端末の設定や運用によっては身元が特定されることがある。
- 以上の内容を、初回起動時および素材・拡張機能の公開時に表示する。

### 6.3 利用者側のフィルタリング

中央からの規制は行わないが、**利用者が自分の意思で**表示・保持・中継しないデータを選べる仕組み（ローカルのブロックリスト、信頼する人が公開したリストの購読など）は提供する（F-P2P-10）。これは「他人に規制を強制しない」「自分が関わるデータは自分で選ぶ」という方針と両立する。

### 6.4 参考

Winny の開発者は著作権法違反幇助の罪に問われたが、最高裁で無罪が確定した（2011 年）。本プロジェクトでも、ツールは中立な技術として提供し、配布物や説明文で違法行為を勧めたり誘導したりしないこととする。

## 7. 対象外（本版では扱わないもの）

- 作品そのものの P2P 配布（作品の公開には、書き出したファイルや既存の投稿サービスを使う）
- 作品・素材・拡張機能の売買・投げ銭などの決済機能（将来検討）
- アニメーション制作機能
- 3D モデルの読み込み・配置
- AI による自動着色・自動生成機能
