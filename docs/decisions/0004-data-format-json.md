# 保存形式に JSON を使う

- 日付：2026-09-24
- 状態：採用

## 背景

作品データ（線・コマ割り・貼り付けた素材の配置）を Git で履歴管理する。Git は文字データの差分表示と統合が得意。

## 判断

- 作品データは JSON で保存する。Rust では serde と serde_json で読み書きする。
- 線は画素ではなく、点の座標の並び（ベクター）として保存する。
- コマ割りとコマ内容は別ファイルにする。

## 理由

- 文字データなので、Git の差分表示と統合がそのまま使える。
- 線をベクターで持つと、消しゴムを「触れた線を丸ごと消す」処理で実現でき、コマの切り抜き・拡大も座標計算で済む。
- コマ割りとコマ内容を別ファイルにすると、構想の「コマ割りとコマ内容を別々に履歴管理する」（F-MANGA-03〜05）を試作の段階から満たせる。
- 人間が読んで確認できる。

## 影響

- 線の数が非常に多くなるとファイルが大きくなる。必要になった段階で、バイナリ形式やタイル分割（F-VCS-09）を検討する。
- 画素単位の消しゴムは、この形式の上で後の版に検討する。
