# 拡張機能は配布せず、公開 API だけを用意する

- 日付：2026-09-26
- 状態：採用

## 背景

構想では当初、素材と拡張機能の両方を P2P で配布する予定だった。拡張機能はプログラムであり、P2P での感染は実行ファイルや圧縮ファイルに集中していたという計測研究がある（[調査レポート](../research/p2p-safety.md) 3.3）。

## 判断

- P2P で配布するのは**素材だけ**とする。
- 拡張機能については、本ツールは**公開 API（インターフェース）だけ**を用意し、入手経路は指定しない。公式の配布場所も持たない。
- どこから入手した拡張機能でも利用者を守れるよう、拡張機能はサンドボックス内で実行し、利用者が許可した権限だけを使えるようにする。

## 理由

- 本ツールが配布するものを、リスクの小さいデータ（素材）に限れる。
- 拡張機能の作者は、自分のサイトや既存のホスティングサービスなど、好きな方法で配布できる。特定の配布場所に縛られないという点で、中央に頼らない方針とも一致する。
- 本ツールが実行可能なプログラムの流通を担わないため、ツールの提供者としての責任の範囲が明確になる。

## 影響

- 構想（[vision.md](../vision.md)）の 4.3・4.5.2・6 章を、この方針に合わせて変更する。
- 公開 API の仕様を文書として公開する必要がある（vision.md F-EXT-07）。
- 拡張機能の入手先の信頼性は、利用者が自分で判断する。本ツールは、導入時の権限の表示と同意（F-EXT-03）で判断を助ける。
