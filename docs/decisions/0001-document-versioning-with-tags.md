# 文書の版はタグで管理する

- 日付：2026-09-24
- 状態：採用

## 背景

最終ゴール（構想）は大きく、まずは最低限の試作品を早く作りたい。試作品の版ごとに要件定義・仕様・設計が変わるため、版ごとの文書をどう管理するかを決める必要があった。

## 判断

- 最終ゴールは [vision.md](../vision.md) に置く。
- 要件定義・仕様・設計（`requirements.md`・`spec.md`・`design.md`）は 1 組だけ置き、今作っている版のことだけを書く。
- 版が完成したら `v0.1.0` のような Git のタグを付け、次の版に向けて文書を書き換える。
- 版の番号は `vメジャー.マイナー.パッチ` の 3 つの数字で表す。機能を加えた版はマイナー、修正だけの版はパッチを上げる。

## 理由

- 版ごとにフォルダを分けると、同じ内容のコピーが増え、直し忘れが起きやすい（DRY）。
- 過去の版の文書は、タグから取り出せる。GitHub でもタグを選んで閲覧できる。
- Git で管理しているプロジェクトなので、Git の仕組みで版を管理するのが最も自然。
- 3 つの数字の形式は、多くのソフトウェアやパッケージ管理ツール（Cargo を含む）が使うセマンティック バージョニングに合わせたもの。

## 影響

- 過去の版の文書を見るときは、`git show v0.1.0:docs/requirements.md` のようにタグを指定する。
- 版の完成時に、タグ付けと文書の書き換えを作業手順に含める。
